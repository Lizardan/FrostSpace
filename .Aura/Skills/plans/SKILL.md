# Планы в FrostSpace

Источник правил — `Assets/.Aura/plans/README.md`; обязательные правила проекта — `AGENTS.md` §«Планы в работе».

## Где лежат планы

Единственное место — **`Assets/.Aura/plans/`**. Туда пишет Aura (`create_or_edit_plan`, путь зашит в
инструмент и не настраивается), туда же кладут планы остальные агенты и человек. Никаких зеркал,
junction'ов и копий: один файл — один план.

Папка начинается с точки — Unity её не импортирует, `.meta` не нужны. `rg`/`git grep` скрытые
каталоги по умолчанию пропускают: при поиске указывай путь явно (`rg --hidden ... Assets/.Aura/plans`).

## Имя файла

- Свой файл (`write_file`) — `Assets/.Aura/plans/YYYY-MM-DD-<тема>.md`.
- Через `create_or_edit_plan` — `plan_name` = `YYYY-MM-DD-<тема>`; инструмент добавит `_vN`
  (`.../YYYY-MM-DD-<тема>_v1.md`). Это допустимая форма имени.

## Обязательные секции

Цель; этапы чекбоксами `- [ ]`; затрагиваемые файлы; критерии приёмки; риски; «Журнал выполнения».

## Процесс

1. При старте сессии: если в `Assets/.Aura/plans/` есть файл плана (кроме README.md) — прочитать и
   продолжить с первого невыполненного пункта, новый не создавать. Один файл — один текущий план.
2. Создать план: через `create_or_edit_plan` (если нужен режим планирования и кнопка запуска) или
   напрямую `write_file` в `Assets/.Aura/plans/`. Результат один и тот же.
3. По ходу работы отмечать `- [x]` и дописывать «Журнал выполнения».
4. После выполнения и проверки удалить файл плана; `Assets/.Aura/plans/README.md` остаётся.
5. Не вести архив завершённых планов.

## Ревью плана — у каждого рантайма своё

Общий контракт один: план — это файл в `Assets/.Aura/plans/`. Как его показать человеку и как
получить «ок» — решает рантайм, к правилам проекта это не относится.

| Рантайм | Чем показывает план | Как приходит апрув |
|---|---|---|
| Aura | `create_or_edit_plan` — свой UI плана | кнопка запуска в UI Aura |
| Freebuff | встроенный планировщик | его собственный UI |
| OpenCode Desktop | Plannotator, инструмент `submit_plan` | Approve в ревью (см. ниже) |
| Codex, Gemini CLI, Cursor, WorkBuddy, … | план в чате | подтверждение словами |

**Не ищи инструменты чужого рантайма.** Нет `create_or_edit_plan` — пиши файл через
`write_file`. Нет `submit_plan` — не считай это ошибкой: отсутствие ревью не отменяет
правила планов и не блокирует работу.

## Plannotator — только OpenCode

Дальше — про OpenCode Desktop и только про него. Плагин `@plannotator/opencode` (workflow
`plan-agent`, `planningAgents: ["plan"]`) живёт в глобальном конфиге OpenCode; Aura, Freebuff
и остальные его не видят. У агента `plan` в OpenCode есть `submit_plan` — он открывает
интерактивное ревью плана в браузере.

Порядок, совместимый с правилами проекта:

1. План по-прежнему пишется файлом в `Assets/.Aura/plans/YYYY-MM-DD-<тема>.md` — это источник
   для следующего агента и для продолжения после прерывания сессии.
2. Затем **то же содержимое** отправляется в `submit_plan` одним edit:
   `{ "edits": [{ "start": 1, "content": "<полный текст плана>" }] }`. Отдельный файл под
   Plannotator не создаётся.
3. Замечания ревью вносятся сначала в файл плана, потом в `submit_plan` точечными диапазонами
   строк. Файл и открытое ревью не должны расходиться.
4. Approve в браузере: Plannotator сам переключает сессию в `build` и отправляет
   «Proceed with implementation». Дополнительно ничего запускать не нужно — это и есть старт
   выполнения плана.
5. После выполнения и проверки файл плана удаляется как обычно (см. «Процесс»).

Если `submit_plan` недоступен (не OpenCode, плагин не загрузился или сессия не в режиме `plan`) —
работать по прежнему порядку: файл плана и обычное подтверждение в чате. Отсутствие ревью не
отменяет правила планов.

Свою копию плана Plannotator хранит вне репозитория (`~/.plannotator/plans/<project>/`);
в проекте остаётся только `Assets/.Aura/plans/`. Копии и архивы в проекте не создавать.

Ревью открывается в **системном** браузере: его запускает сам Plannotator, а Desktop 2.1.4
не отдаёт URL во встроенную browser-панель (ссылки идут через `shell.openExternal`).
В транскрипте появляется `Plannotator session ready: <url>` — этот адрес человек вставляет
в панель сам (команда «Open browser» → адресная строка, `mod+L`). Автоматическое открытие
в панели не обещать.

## Запреты

- Не создавать второй файл плана и не переносить план копированием.
- Не удалять и не перемещать `Assets/.Aura/plans/` — на неё ссылаются `AGENTS.md`, `README.md`,
  `docs/PROJECT_MAP.md`.
- Не класть `.meta` внутрь `Assets/.Aura/` и не пытаться «импортировать» эту папку в Unity.
