# Документация FrostSpace

Индекс документации. Каждый документ отвечает на свой вопрос; не дублируй содержимое
одного документа в другом.

## Что читать

| Вопрос | Документ |
|---|---|
| Что за проект и в каком он состоянии | [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md) |
| Как устроены слои и зависимости | [ARCHITECTURE.md](ARCHITECTURE.md) |
| Где что лежит, с чего начинается игра | [PROJECT_MAP.md](PROJECT_MAP.md) |
| Как собрать, запустить тесты, проверить | [DEVELOPMENT.md](DEVELOPMENT.md) |
| Как ассеты переходят из Blender в Unity | [ASSETS.md](ASSETS.md) |
| Как работать с Blender и его MCP | [BLENDER.md](BLENDER.md) |
| Как работать с Unity MCP | [UNITY_MCP.md](UNITY_MCP.md) |
| Почему принято то или иное решение | [decisions/README.md](decisions/README.md) |

## Порядок чтения для новой задачи

1. `AGENTS.md` — обязательные правила, безопасность, модель работы.
2. Этот файл — чтобы выбрать нужный документ.
3. Для локальной задачи: `PROJECT_MAP.md` → нужный раздел `ARCHITECTURE.md`.
4. Для ассетов: `ASSETS.md`, затем `BLENDER.md` или `UNITY_MCP.md`.
5. Для сборки/проверки: `DEVELOPMENT.md`.
6. Если меняется контракт или архитектурное решение — `decisions/`.

Для маленькой локальной правки не нужно читать все документы: достаточно `AGENTS.md`,
`PROJECT_MAP.md` и профильного раздела.

## Правила ведения документации

- **Один документ — один вопрос.** Если документ отвечает на два — раздели.
- **Один источник истины.** Дерево структуры — только `PROJECT_MAP.md`; Blender-грабли —
  только `BLENDER.md`; Unity MCP — только `UNITY_MCP.md`; контракт ассетов — только
  `ASSETS.md`; сборка/тесты — только `DEVELOPMENT.md`.
- **Расхождение с кодом — дефект.** Исправь документ или явно зафиксируй причину.
- **Не копируй `AGENTS.md`.** Ссылайся на него.
- **Устаревший документ удаляй**, а не оставляй «на всякий случай».
- **Даты и версии — только проверенные.** Если факт не подтверждён, пиши «не проверено»
  или «требует подтверждения».
