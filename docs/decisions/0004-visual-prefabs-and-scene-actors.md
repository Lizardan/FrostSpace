# 0004. Визуальные префабы и сценовые акторы

- Статус: Accepted
- Дата: 2026-10-18

## Контекст

Префабы роботов содержали и визуал, и игровую логику: `CharacterController`,
`RobotLocomotion`, тег `Player`. На сцене стояли четыре экземпляра таких префабов, поэтому
каждый NPC читал те же `InputSystem_Actions`, что и игрок, — ввод двигал всех роботов
сразу, а `CharacterController` на префабе делал причину неочевидной. Тег `Player` стоял на
каждом префабе, поэтому любой поиск по тегу мог вернуть не тот объект.

Разделение «визуал / логика» нужно закрепить так, чтобы его нельзя было размыть
случайной правкой.

## Решение

1. **Префаб — только визуал.** `Assets/_Project/Content/Prefabs/Robots/R*_Model.prefab` —
   варианты FBX-модели (`PrefabAssetType.Variant`) с `Animator` и контроллером
   `R*.controller` (`applyRootMotion = false`). Без `CharacterController`, без
   `RobotLocomotion`, без тега.
2. **Логика — на сценовом актёре.** `SnowLevelBuilder` создаёт актёров:
   - `Player` — тег `Player`, `CharacterController`, `RobotLocomotion`, явные ссылки
     `_actions`, `_animator`, `_camera`; визуальный префаб — дочерний объект
     (`Player/R1_PolarMechanic_Model`).
   - `NPC_R2_Furnace`, `NPC_R3_Scout`, `NPC_R4_Hauler`, `NPC_R5_Ranger` (под корнем
     `NPC`) — только `Transform` и визуальный ребёнок; никакого ввода и физики.
3. **Root Motion не используется.** Клипы роботов in-place, движение — kinematic через
   `CharacterController`; согласование стопы и корпуса — через `Animator.speed`
   (фактическая скорость / скорость клипа).
4. Имена фиксированы: FBX не переименовываются, префаб = имя модели + `_Model`,
   контроллеры остаются `R*.controller`.
5. Правило проверяется EditMode-тестом (`FrostSpace.Tests.EditMode`), а не
   договорённостью: у визуального префаба есть `Animator` и нет `CharacterController`,
   `RobotLocomotion` и тега `Player`.

## Последствия

- Будущий `NpcController` вешается на сценовый актёр `NPC_*`, а не на префаб.
- Сцена воспроизводима: пересобрал префабы → пересобрал сцену билдером.
- Визуал можно менять или подменять, не рискуя отдать управление NPC.
- Минус: один лишний уровень вложенности (`Player → R1_PolarMechanic_Model`).

## Альтернативы

- **Оставить логику на префабе и выключать её флагом «isPlayer»** — отклонено: ввод и
  физика продолжают жить на каждом NPC, ошибку легко повторить при следующем префабе.
- **Обёртка-префаб вокруг FBX-инстанса** — отклонено: лишняя сущность, вариант модели
  проще и сразу подхватывает изменения импорта FBX.
