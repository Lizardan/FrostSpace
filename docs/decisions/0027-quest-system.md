# 0027. Квесты: ScriptableObject-данные, сценовый директор, действия диалога

- Статус: Accepted
- Дата: 2026-10-29
- Связано: [GAME_DESIGN.md](../GAME_DESIGN.md), [0025](0025-dialogue-system.md),
  [0026](0026-story-scene-flow.md).

> **Дополнение 2026-10-29.** Владелец решил, что в депо при прибытии робот выдаёт
> **карту местности и сканер** одним разговором. К списку действий добавляется
> `GrantMap`; `GrantScanner` и `GrantMap` идемпотентны и срабатывают один раз за
> диалог. Выдача перенесена из сцены станции в депо (`DP-03`), поэтому отдельный бит
> `RD-01` снят.

## Контекст

Диалоги уже умеют ветвиться (ADR 0025), но ничего не меняют в мире: `DialogueSession`
возвращает только текущий узел. Квеста как сущности нет — ни данных, ни прогресса, ни
HUD. Первый срез требует ровно одного квеста: поговорить → перенести четыре
аккумулятора → поговорить.

AGENTS.md запрещает event bus, service locator и «абстракции на будущее». Значит
квест не может быть глобальной шиной: его должен вести объект сцены, у которого есть
явные ссылки на участников.

## Решение

1. **Данные квеста — `QuestAsset` (ScriptableObject).**

   ```
   QuestAsset
     questId        строка, уникальная в проекте
     title          строка для HUD
     objectives[]   QuestObjective
   QuestObjective
     id             строка, уникальная внутри квеста
     text           строка для трекера
     kind           Talk | Deliver | Reach
     targetId       id собеседника, предмета или зоны
     required       целое > 0
   ```

   `Reach` заведён сразу, потому что Stage 3 добавляет «доехать до станции»; отдельный
   ADR для этого не нужен.

2. **Прогресс — `QuestLog`, обычный C#-класс, а не MonoBehaviour.**
   Состояния: `Inactive → Active → Completed`. Цели выполняются **по порядку**: событие
   следующей цели игнорируется, пока не закрыта текущая. `QuestLog` умеет
   `Apply(QuestEvent)` и `Snapshot`, не знает про Unity-сцену и поэтому тестируется в
   EditMode без Play Mode.

   `QuestEvent` — структура: `kind`, `targetId`, `amount`. Никаких подписок: директор
   вызывает `Apply` напрямую.

3. **`QuestDirector` — компонент сцены.** Хранит `QuestAsset`, создаёт `QuestLog`,
   подписывается на **явные** события участников (`DialogueController.ActionInvoked`,
   `CarrySlot.Placed`) и передаёт их в лог. Он же решает, что делать при завершении
   квеста: включить маркер у R13, открыть дверь, запустить финал сцены. Ссылки —
   `[SerializeField]`, без `FindObjectOfType`.

4. **Действие живёт на узле диалога.** В `DialogueNode` добавляются
   `DialogueAction _action` (`None`, `AcceptQuest`, `CompleteQuest`, `GrantScanner`) и
   `string _questId`. `DialogueController` вызывает событие `ActionInvoked` **один раз
   за показ узла**; повторный показ того же узла в новой сессии — снова одно событие.
   Действие идемпотентно: `AcceptQuest` для активного квеста ничего не делает,
   `CompleteQuest` для незавершённого — тоже.

   Пустой `questId` означает «квест, назначенный сцене». Старые четыре диалога
   (R2–R5) остаются с `None` и не требуют правки.

5. **HUD — `QuestTracker`.** Отдельный компонент поверх `PlayerHud`, читает `QuestLog`
   и показывает `title` и прогресс текущей цели (`BATTERIES 2/4`). Трекер не хранит
   состояние: единственный источник истины — `QuestLog`.

6. **Сброс статики.** Если у `QuestLog` появится статический реестр (например, для
   отладки), он сбрасывается в
   `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]`. По умолчанию лог —
   экземпляр директора, статики нет.

7. **Валидация.** `QuestAsset.OnValidate` проверяет: непустой `questId`, хотя бы одну
   цель, уникальные `id` целей, `required > 0`. Отдельный Editor-инспектор не нужен;
   ошибки видны в Console при сохранении ассета.

## Последствия

- Квест нельзя «пройти дважды»: состояние живёт в одном логе на сцену, а действия
  идемпотентны.
- Порядок целей жёсткий. Если понадобится параллельная цель, это новое решение, а не
  настройка ассета.
- Тесты квестов — EditMode: `QuestLog.Apply` по шагам, игнор события вне очереди,
  завершение, повторное применение.
- `DialogueNode` меняет сериализованную схему. Старые ассеты читаются с `None` по
  умолчанию, но инспектор диалога нужно расширить полями действия и `questId`.
- Глобального event bus не появилось: участники сцены знают друг о друге явно.

## Альтернативы

- **Глобальный event bus / статический `QuestService`.** Отклонено: AGENTS.md прямо
  запрещает, а на один квест это лишняя связность и лишняя статика при выключенном
  domain reload.
- **Квест как часть `DialogueAsset`.** Отклонено: квест переживает диалог, у него своя
  цель и свой HUD; держать его в графе реплик — смешивать авторские данные с прогрессом.
- **Условия в узлах диалога («покажи, если квест активен»).** Отклонено на этом этапе:
  первый срез обходится двумя отдельными ассетами диалога (до и после погрузки).
  Когда понадобится третья ветка — отдельное решение.
- **Параллельные цели.** Отклонено: «погрузи 4 из 4» — линейный сценарий, очередь
  проще и предсказуемее.
