# Architecture Decision Records

Здесь фиксируются решения, которые дорого переигрывать: контракты, границы, выбор
инструментов и форматов. ADR отвечает на вопрос **«почему так»**, а не «как это
устроено» (устройство — в `ARCHITECTURE.md` и профильных документах).

## Когда создавать ADR

- Меняется контракт между слоями, форматом ассетов или пайплайном.
- Выбирается инструмент/формат, который затронет несколько задач.
- Приходится сознательно отклонить очевидный вариант — причина важнее выбора.

Локальный баг или мелкая правка ADR не требуют.

## Шаблон

```markdown
# NNNN. Краткое название

- Статус: Proposed | Accepted | Superseded by NNNN
- Дата: YYYY-MM-DD

## Контекст
Что вынудило принять решение. Факты, ограничения, что уже проверено.

## Решение
Что именно решено. Достаточно конкретно, чтобы это можно было проверить.

## Последствия
Что становится проще, что сложнее, какие ограничения появляются.

## Альтернативы
Что рассматривалось и почему отклонено.
```

## Правила

- Один ADR — одно решение.
- Не переписывай принятый ADR задним числом: создавай новый со статусом
  `Superseded by`.
- Ссылайся на ADR из профильных документов, не копируй его текст.
