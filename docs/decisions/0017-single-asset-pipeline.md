# 0017. Единая точка входа пайплайна ассетов: `build_all.py`

- Статус: Accepted
- Дата: 2026-10-22
- Дополняет: [0001](0001-blender-authoring.md), [0003](0003-automation-modes.md)

## Контекст

К 2026-10-22 в `Tools/Blender/` накопилось восемь сборочных скриптов (`build_robots`,
`build_animals`, `build_level`, `build_hoverbike`, `build_motorcycle`, `build_menu_open`,
`build_menu_views`, `build_wreck_parts`) и восемь вспомогательных (`selftest`,
`render_robot_previews`, `render_animal_previews`, `render_level_previews`,
`render_robot_lineup`, `make_robot_sheet`, `measure_locomotion`, `fbx_units`).

ADR 0001 и 0003 зафиксировали, **что** является воспроизводимым артефактом (bpy-скрипт) и
**какой транспорт** основной (headless). Но не зафиксировали, **какой командой** этот
артефакт производится. Практическое следствие: чтобы пересобрать ассет, нужно помнить
пару «ассет → скрипт → аргументы → куда пишет → чем проверяется». Память — не контракт:
новый агент или человек не выводит эту пару из репозитория и каждый раз восстанавливает
её заново, а часть шагов (проверка единиц, превью) вообще выпадает из процесса.

Дополнительно выяснено при инвентаризации MCP:

- Аддон `blender_mcp` не содержит ни одной команды моделирования, риггинга или анимации.
  Единственная команда, меняющая геометрию, — `execute_code`; остальное — инспекция,
  библиотеки ассетов (Poly Haven / Sketchfab / Poly Pizza) и AI-генераторы
  (Hyper3D / Tripo / Hunyuan3D / Meshy) плюс `export_scene`.
- Значит «работать инструментами вместо скрипта» технически невозможно: авторинг всегда
  идёт через `bpy`. Отличие MCP — гранулярность цикла обратной связи (много мелких правок
  в живой сессии + скриншот вьюпорта), а не качество геометрии.

## Решение

1. **Один вход: `Tools/Blender/build_all.py`.** Запускается системным Python, сам находит
   `blender.exe` (`--blender` → env `BLENDER_EXE` → `PATH` → типовые каталоги установки) и
   вызывает профильные скрипты в `--background --factory-startup`. Путь и версия Blender
   остаются параметром окружения.
2. **Шаги пайплайна фиксированы и идут в одном порядке:** сборка → проверка артефактов →
   превью. Реестр ассетов (`PIPELINE`) в самом скрипте — единственное место, где записано
   соответствие «ассет → скрипт → выходные файлы → шаги проверки и превью».
3. **Правило приёмки ассета.** Ассет считается сделанным, только если он появился из
   прогона `build_all.py`, прошёл `--check` и оставил превью (`--preview`). Разовая правка
   в GUI-Blender — черновик, пока не закреплена скриптом и не перепроверена headless.
4. **MCP остаётся инструментом, а не пайплайном.** Его роль: визуальная итерация,
   инспекция чужого `.blend`, библиотечные и AI-ассеты. Всё, что должно сохраниться,
   переносится в скрипт и перепроверяется `build_all.py`.
5. **Профильные команды не удаляются.** `blender --background --python build_X.py`
   продолжает работать: `build_all.py` — надстройка, а не замена. Нужна она для того,
   чтобы пайплайн не зависел от памяти запускающего.

## Последствия

- Один и тот же прогон у человека, у любого агента и в CI; шаги и выходные файлы
  перечислены в репозитории, а не в переписке.
- Проверки (`selftest.py`, `fbx_units.py`, `measure_locomotion.py`) перестают быть
  необязательными: они часть флага `--check`.
- Появляется требование поддерживать реестр: новый ассет обязан быть добавлен в
  `PIPELINE`, иначе он «не существует» для пайплайна.
- Превью остаются отдельным флагом: рендер роботов — процесс на файл, это минуты.

## Альтернативы

- **Живая MCP-сессия как основной путь.** Отклонено: результат живёт только как состояние
  `.blend`, нет артефакта и кода возврата, нет воспроизводимости и CI, каждая операция —
  round-trip через один GUI-поток, модальный диалог вешает мост.
- **Только инструменты-генераторы (Meshy / Tripo / Hyper3D).** Отклонено: даёт форму, но не
  модель под анимацию — трисовая топология без управляемых UV и весов; не покрывает риггинг,
  скиннинг и клипы, которые нужны роботам и животным.
- **Оставить восемь отдельных команд.** Отклонено: пайплайн зависит от памяти, шаги
  проверки и превью выпадают, новый агент не выводит процесс из репозитория.
