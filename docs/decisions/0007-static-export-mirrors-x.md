# 0007. Зеркало X при экспорте статики: оси Blender → Unity

- Статус: Accepted
- Дата: 2026-10-18

## Контекст

ADR 0002 зафиксировал единицы и оси, а для статики — обязательный
`bake_space_transform=True`. На ассетах роботов это сходилось: габарит после импорта
совпадал. На уровне это совпадение скрыло ошибку: **габарит сходится и у зеркальной
модели** — любой bbox симметричен относительно отражения.

Ошибку нашли на асимметричных признаках. Пробой в Unity измерено, что конвейер
`bake_space_transform=True` даёт

```
Unity(x, y, z) = (−x_blender, +z_blender, −y_blender)     det = −1
```

то есть конверсия осей **левосторонняя**: модель приезжает отражённой. В сцене это
выглядело так: крыльцо, дверь и труба оказались на другой стороне дома по X (крыльцо
+1.40 вместо −1.40, фундамент −0.09 вместо +0.09, дверь +0.90 вместо −0.94, труба
−1.43 вместо +1.42), а дым из трубы висел в четырёх метрах от самой трубы. Размеры,
высоты и габариты при этом были верными.

## Решение

1. **Статика зеркалится по X в экспортёре**, до вызова `export_scene.fbx`:
   `level_lib._mirror_x_inplace` отражает меш и грани, `reverse_faces` возвращает
   нормали наружу. Тогда конверсия становится правосторонней и совпадает с ADR 0002:
   Blender `+X → +X`, `+Y → −Z`, `+Z → +Y`.
2. **Координаты авторинга и конверсия раскладки не меняются**:
   `to_blender(x, z) = (x, −z)` и заносы рельефа `(x, −z)` остаются как были. Зеркало —
   деталь экспортёра, а не новое соглашение о том, «где плюс».
3. **Проверка ориентации — по асимметричному признаку**, а не по габариту: в уровень
   закладывается заведомо несимметричная деталь (крыльцо, труба, занос рельефа), и после
   импорта сверяются её мировые координаты. Совпадение габарита эту ошибку не ловит.
4. Правило относится к **статике уровня** (`export_static`). Скелетные FBX роботов
   экспортируются другим скриптом; их ориентация проверяется визуально в сцене, и это
   правило на них не распространяется без отдельной проверки.

## Последствия

- Модели уровня приезжают без отражения; «левая» сторона остаётся левой.
- Любой новый статический ассет обязан идти через `export_static` — ручной вызов
  `export_scene.fbx` без зеркала вернёт ошибку.
- Появляется лишний шаг проверки: асимметричный признак + сверка мировых координат
  после импорта (габаритные замеры остаются, но их недостаточно).
- Зеркало применяется к геометрии до экспорта, поэтому в самом FBX «право/лево»
  относительно `.blend`-источника перевёрнуто. Это осознанная плата за правый результат
  в Unity.

## Альтернативы

- **Компенсация в Unity (отрицательный `localScale.x` на корне объекта).** Отклонено:
  минус-масштаб ломает освещение, батчинг и физику, а исправлять пришлось бы каждую
  инстанцию и каждого потребителя FBX.
- **Поворот на 180° вместо зеркала.** Отклонено: у отражения и поворота разные матрицы,
  поворот не исправляет отражение.
- **Смириться и разворачивать сцену вручную.** Отклонено: ошибка возвращается с каждым
  новым ассетом, а обнаруживается глазами, то есть поздно.
