# 0031. Сохранение прогресса демо: один ключ PlayerPrefs, «Продолжить» в меню

- Статус: Accepted
- Дата: 2026-10-29
- Связано: [GAME_DESIGN.md](../GAME_DESIGN.md), [0026](0026-story-scene-flow.md),
  [0027](0027-quest-system.md).

## Контекст

Демо стало длинным: выбор корпуса → поезд → квест → депо → дорога → станция. В WebGL
закрытая вкладка обнуляет сессию, и пройти всё заново — наказание. Владелец попросил
сохранять прогресс квеста и продолжать с места.

Позиция игрока и подобранные предметы для этого не нужны: у каждой сцены есть точка
появления, предметы стоят на исходных местах, а состояние квеста — это несколько чисел.

## Решение

1. **Один ключ.** `PlayerPrefs`, ключ `FrostSpace.Save`, значение — JSON:

   | Поле | Значение |
   |---|---|
   | `version` | целое, сейчас `1` |
   | `scene` | `Train` или `Frontier` |
   | `characterId` | `R1_PolarMechanic`, `R15_Courier`, `R10_Pipewright` |
   | `questId` | `train_batteries` |
   | `state` | `Active` или `Completed` |
   | `objective` | индекс текущей цели |
   | `progress` | счётчик текущей цели |

2. **Когда пишется.** При каждом изменении квеста (принят, предмет поставлен, квест
   закрыт) и при выходе из сцены. Запись идёт через `PlayerPrefs.Save()` сразу, а не
   «когда-нибудь»: вкладку могут закрыть в любой момент.

3. **Когда читается.** `QuestDirector` — при старте сцены, чтобы восстановить счётчик;
   меню — чтобы решить, активен ли пункт `ПРОДОЛЖИТЬ`.

4. **Меню.** `НАЧАТЬ` стирает ключ и ведёт в `CharacterSetup`. `ПРОДОЛЖИТЬ` грузит
   сцену из сохранения и восстанавливает квест. Без сохранения пункт неактивен.

5. **Что не сохраняется.** Позиция, поворот, предметы в руках, открытые двери.
   Сцена стартует со своей точки появления; предметы — на исходных местах; квест
   восстанавливает только счётчик.

6. **Версия.** При несовпадении `version` сохранение игнорируется и стирается:
   лучше начать заново, чем восстановить половину.

7. **Сброс статики.** Любое кэширующее поле сбрасывается в
   `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` — domain reload выключен.

## Последствия

- `MainMenuScreen` получает второе действие и проверку наличия сохранения; сцена меню
  меняется в редакторе.
- Появляются EditMode-тесты: сериализация/десериализация, битый JSON, несовпадение
  версии, сброс.
- В WebGL `PlayerPrefs` живёт в IndexedDB и стирается вместе с данными сайта — это
  ожидаемое поведение, а не баг.
- «Продолжить» не возвращает игрока туда, где он стоял: он появляется на спавне сцены.
  Для коротких сцен это приемлемо; для открытой карты позже понадобится точка входа.

## Альтернативы

- **Сохранять позицию и предметы.** Отклонено: дороже, а сцены короткие; спавн решает
  задачу.
- **Отдельный save-сервис на весь проект.** Отклонено: один ключ и один формат, сервис
  здесь — лишняя абстракция.
- **Без сохранения.** Отклонено владельцем.
