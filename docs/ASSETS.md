# Контракт ассетов Blender → Unity

Здесь только правила перехода ассетов в Unity. Как запускать Blender и его грабли —
`BLENDER.md`. Структура папок — `PROJECT_MAP.md`.

## Единицы и оси

| Понятие | Blender | Unity |
|---|---|---|
| Единица | 1 unit = 1 м (при `unit_settings.scale_length = 1.0`) | 1 unit = 1 м |
| Вверх | +Z | +Y |
| Вперёд | −Y | +Z |
| Вбок | +X | +X |

FBX-экспортёр конвертирует оси. Не «поправляй» поворот объекта на глаз: проверяй
габарит и ориентацию после импорта в Unity.

**Отражение по X — отдельная ловушка.** `bake_space_transform=True` даёт левостороннюю
конверсию осей: модель приезжает зеркальной, при этом габарит совпадает, и bbox-проверка
её не ловит. Поэтому статика экспортируется только через `export_static` (зеркало X +
переворот граней), а ориентация проверяется по **асимметричному признаку** (крыльцо,
труба, занос рельефа). Причина и числа — ADR 0007.

## FBX: статика

Для статической геометрии:

- `bake_space_transform=True` — обязательно. Без него экспортёр объявляет файл Y-up, а
  вершины пишет в осях Blender; объект приезжает «на ребро».
- зеркало X (`export_static(..., mirror_x=True)`) — обязательно для статики: компенсирует
  отражение от `bake_space_transform` (ADR 0007).
- `apply_unit_scale=True`, `global_scale=1.0` — единицы не должны меняться «по пути».
- `mesh_smooth_type="FACE"` — flat shading для low-poly.
- `use_selection=True` — в файл попадает только выбранное, а не вся сцена.

Проверка — не глазами в Blender, а габаритом после импорта: сравни `obj.dimensions` до
экспорта и мировой bbox после обратного импорта. `Tools/Blender/selftest.py` делает это
автоматически с допуском 5 мм.

## FBX: скелет и анимация

- Экспортируй только меш и арматуру (`use_selection=True`), иначе в файл попадут чужие
  объекты сцены.
- Без NLA экспортёр перебирает **все** действия файла: в один FBX могут попасть клипы
  чужих моделей. Если клипов несколько — используй NLA-полосы этой арматуры.
- Ключи ставь на все деформирующие кости во всех клипах. Иначе Unity «протекает» позами
  между клипами: кость, у которой нет ключа в текущем клипе, сохраняет значение из
  предыдущего.
- Проверяй ≤4 влияния веса на вершину — это требование Unity-скина.
- После экспорта проверь имена клипов и число каналов (например, разбором GLB), а не
  только факт создания файла.

## Роботы FrostSpace: FBX с клипами

Двадцать роботов собраны скриптом, а не импортированы из `AssetSource/`:

- Генерация: `Tools/Blender/build_robots.py` (ядро `robot_lib.py`, дизайны
  `robot_designs.py`), выход — `Assets/_Project/Content/Models/Robots/R*.fbx`.
- Имена не меняются. Принятая партия: `R1_PolarMechanic.fbx`, `R2_Furnace.fbx`,
  `R3_Scout.fbx`, `R4_Hauler.fbx`, `R5_Ranger.fbx`. Вторая партия (принята
  2026-10-18, все 15 остаются):
  `R6_Smelter`, `R7_Drifter`, `R8_Bulwark`, `R9_Tinker`, `R10_Pipewright`,
  `R11_Snowplow`, `R12_Beacon`, `R13_Prospector`, `R14_Medic`, `R15_Courier`,
  `R16_Warden`, `R17_Hermit`, `R18_Forge`, `R19_Tide`, `R20_Cogsmith`.
- В каждом FBX три клипа: `walk_loop`, `idle_loop`, `sprint_loop`; `RobotAssetPostprocessor`
  переименовывает их в `Walk`, `Idle`, `Sprint`, включает loop и конвертирует цвет
  материалов из sRGB в линейный (иначе роботы выглядят выбеленными). Из палитры цвет и
  roughness переносятся (`_Smoothness` = 1 − roughness, сверено по всем материалам),
  а `metallic` — нет: `_Metallic` = 0 у всех роботов.
- Клипы **in-place** (корневое смещение обнулено). Root Motion выключен, движение в игре —
  kinematic; согласование стопы и корпуса — через `Animator.speed` (ADR 0004).
- Скорость стопы в контакте, м/с: Blender `measure_locomotion.py` даёт walk 0.93 /
  sprint 8.92; разовый замер в Unity — 0.91 / 8.92. Источник истины для сцены — замер
  Unity: значения зафиксированы в скрытых полях `_walkClipSpeed`/`_sprintClipSpeed`
  компонента `RobotLocomotion`. Инструмента для повторного замера в проекте нет.
- Визуальные префабы `R*_Model.prefab` — варианты FBX-модели (`PrefabAssetType.Variant`)
  с `Animator` и `R*.controller`; без `CharacterController`, ввода и логики.

## Робо-животные FrostSpace: FBX с клипами

13 животных собраны скриптом на ригах Quaternius из `AssetSource/` (в `ThirdParty/` пак не
импортируется): 12 видов — гибрид «исходная оболочка + робо-броня», паук собран целиком
процедурно. Причина и альтернативы — ADR 0009; источник, лицензия и что именно взято —
`Content/Models/RobotAnimals/SOURCE.md`.

- Генерация: `Tools/Blender/build_animals.py` (ядро `animal_lib.py`, дизайн
  `animal_designs.py`), выход — `Content/Models/RobotAnimals/<Species>/RA_<Species>.fbx`,
  регистр — `Tools/Blender/animal_manifest.json`. Сборка по именам: `-- Wolf Cow`,
  без аргументов — все 13.
- В FBX два клипа — `Idle` и `Move` (take `idle_loop`/`move_loop`); `AnimalAssetPostprocessor`
  даёт имена, включает loop и конвертирует цвет материалов sRGB→linear. Длина клипа у
  каждого вида своя, поэтому границы кадров берутся из FBX, а не из констант в коде.
- **Стоячий хвост клипа срезается.** У фермерской пачки Quaternius `Walk` вдвое длиннее
  цикла: после шагов идут реальные ключи стояния (линейный дрейф ~0.0002 на кадр), в игре
  это читается как «шаг — пауза — шаг». `animal_lib._static_tail` режет такой хвост, но
  только если поза на срезе замыкает петлю (остаток ≤ 5 % амплитуды). Длины после среза
  (кадры `Idle`/`Move`): Cow 149/40, Horse и Zebra 149/32, Llama и Sheep 149/26,
  Pig и Pug 149/35; Wolf 39/39, Cat 39/40, Dog 39/39, Eagle 39/29, Piranha 38/38,
  Spider 60/30 — как в источнике (Spider — 30 fps, остальные 24).
- Клипы **in-place** (корневое смещение обнулено), Root Motion выключен, движение
  кинематическое (ADR 0004); согласование стопы и корпуса — `Animator.speed`.
- Масштаб нормируется по метрике манифеста: `height` (десять видов), `width` (Eagle —
  размах крыльев), `length` (Piranha — длина). `unity_scale` в манифесте — ориентир для
  Blender, а не масштаб префаба: фактический масштаб живёт на префабе и проверяется тестом.
- Ориентация: конвенция «вперёд» у паков разная (+X / −Y / +Y); к +Z модель приводится в
  Blender, а итоговое рыскание зашито в префаб-вариант — 0° у десяти видов, 90° у
  Wolf/Cat/Dog, 180° у Eagle. Сценовые актёры дублируют его явным оверрайдом, чтобы правка
  префаба не развернула животное.
- Визуальные префабы `RA_<Species>_Model.prefab` — варианты FBX-модели с `Animator` и
  `RA_<Species>.controller`; без `CharacterController`, `NpcController` и
  `AirPatrolController`, без тега.

  (обёртка над FBX) собираются меню `FrostSpace → Ride`; подушка и игровые

## Unity: импорт FBX

| Параметр | Значение |
|---|---|
| Scale Factor | 1 (если модель построена в метрах) |
| Forward / Up | +Z / +Y |
| Read/Write | выключено, если `Mesh` не нужен в рантайме |
| Optimize Mesh | включено |
| Import Normals / Tangents | включено, если есть текстуры |
| Compression | Off для героев, Medium для окружения |

**Компенсация масштаба на корне.** Импортёр может положить на корень префаба
компенсацию единиц (в нашем selftest на Blender 5.2.2 локальный меш приехал в
сантиметрах, а на корне появился `scale = 0.01` и поворот 90°). Не затирай её
присваиванием:

```csharp
// правильно: умножить на нужный масштаб
root.localScale = Vector3.Scale(root.localScale, Vector3.one * scale);

// неправильно: компенсация импортёра потеряна, объект станет в 100 раз больше
root.localScale = Vector3.one * scale;
```

Проверяй итоговый мировой габарит, а не локальный масштаб.

## Материалы и цвет

- Проект живёт в **Linear** color space. Цвета из макета/палитры задаются в sRGB и
  конвертируются в C#; иначе картинка молча темнеет (без ошибок и предупреждений).
- В URP текстура назначается так:

```csharp
material.SetTexture("_BaseMap", texture);
```

`material.mainTexture` в URP — молчаливый no-op: свойство есть, но рендер его не читает.

- Материалы переиспользуй. Вариации цвета — через `MaterialPropertyBlock`, а не новый
  материал на каждый объект: иначе ломается батчинг.
- `ReadPixels` в `Texture2D` с флагом `linear: false` возвращает **линейные** значения, а
  `EncodeToPNG` пишет sRGB. Если снимать кадр в `RenderTexture` с
  `RenderTextureReadWrite.sRGB`, PNG получается таким же, как видит игрок.
- **Скриншот `manage_camera` — sRGB, а не линейный** (перепроверено 2026-10-18). Кадр,
  снятый инструментом с той же точки, что и `Main Camera`, совпал с sRGB-рендером в
  `RenderTexture` по распределению (среднее/медиана/перцентили) — файл можно сравнивать с
  палитрой напрямую. Прежняя запись «в файле линейные значения» относилась к другому пути
  съёмки и к `manage_camera` **не применяется**. Симптом ошибки: если перекодировать
  такой PNG «из linear в sRGB» ещё раз, картинка светлеет и теряет насыщенность —
  диагностика начинает врать в сторону «всё блёклое».
- Камера, созданная кодом, не получает `UniversalAdditionalCameraData` автоматически.
  Без него постобработка (например, виньетка) молча не работает. Добавляй компонент
  явно, если настраиваешь URP-эффекты из кода.

## Сторонние паки

| Уровень | Где | Правило |
|---|---|---|
| Сырые архивы | `AssetSource/` (вне git и вне Unity) | не коммитить, не импортировать целиком |
| Импорт | `Assets/ThirdParty/<Pack>/` | только нужные модели, текстуры, материалы |

- Один пак — одна папка. Внутри — `Models/`, `Textures/`, `Materials/` по необходимости.
- В папке пака — `SOURCE.md`: откуда скачано, лицензия, дата, что именно взято.
- Имена файлов — `PascalCase`, без пробелов и кириллицы.
- Скачивание должно быть воспроизводимым: если пак нельзя восстановить по `SOURCE.md`,
  он считается потерянным.

В `AssetSource/` сейчас лежат CC0-паки Quaternius (природа, постройки, интерьер,
персонажи, животные, еда, мебель, RPG-предметы) и архив Ultimate Modular Men. Источник
Ultimate Modular Men в проекте не зафиксирован — при импорте добавь `SOURCE.md` с
подтверждённым источником и лицензией.

### Quaternius: превью в Blender

У части моделей Quaternius материал имеет `Alpha = 0` при режиме `HASHED`: в Blender
превью выглядит пустым. Лечится принудительной непрозрачностью на время превью. **В
Unity это не проблема** — не переноси этот workaround в игровые материалы.

- Папки — `PascalCase`; файлы ассетов — `PascalCase`, без пробелов.
- Модели — `Assets/_Project/Content/Models/`, материалы — `Materials/`, префабы —

- `.meta` коммитится всегда. Не удаляй и не переименовывай вручную.

## Если появится AI-генерация 3D

- Разные генераторы смотрят в разные оси (условно: +X или −Z). Не угадывай: импортируй,
  измерь габарит и ориентацию, только потом собирай префаб.
- Текстуры от генераторов обычно sRGB; в линейном проекте их нельзя считать линейными.
- AI-реконструкция даёт **силуэт**, а не замысел: она не создаёт дизайнерские панели,
  швы и воротники. Не планируй на ней уникальный стиль без доводки руками/кодом.
- Не тащи в проект весь пайплайн генератора: только результат и `SOURCE.md`.

## Статус проверки

Проверено в FrostSpace:

- единицы и оси на FBX-roundtrip (`Tools/Blender/selftest.py`, Blender 5.2.2);
- `bake_space_transform=True` и совпадение габарита до/после импорта;
- компенсация масштаба на корне при обратном импорте (локальный меш в см,
  `scale = 0.01`, поворот 90° — мировой габарит при этом верный);
- существование типа `UniversalAdditionalCameraData` в URP-сборке (через `unity_reflect`);
- клипы роботов: `Idle`/`Walk`/`Sprint` нужной длины, in-place (EditMode-тесты, 2026-10-18);
- клипы животных: `Idle`/`Move` нужной длины, loop, in-place, без статичного провала в
  `Move` (EditMode `AnimalVisualPrefabTests`, 2026-10-19);
- габариты префабов животных совпадают с `target`/`metric` манифеста (тот же тест) и
  маршруты в Play Mode проходят все 13 актёров (2026-10-19);
- замер скорости стопы клипов в Blender и Unity: 0.93 / 8.92 против 0.91 / 8.92 м/с
  (2026-10-18);
- компенсация масштаба у FBX робота: локальный меш со `scale = 0.01` и поворотом 90°,
  мировой габарит верный (`probes/probe_fbx_import.py`);
- отражение статики по X от `bake_space_transform`: конвейер даёт
  `Unity(x,y,z) = (−x_bl, z_bl, −y_bl)`; лечится зеркалом X при экспорте (ADR 0007,
  2026-10-18);
- ориентация уровня после импорта: крыльцо −1.40, дверь −0.94, труба +1.42, фундамент
  +0.09 — совпадает с задуманным (2026-10-18);
- палитра `Level_*`: цвета из Unity-палитры, импорт с sRGB→linear
  (`LevelAssetPostprocessor`, 2026-10-18);
- палитра роботов переносится 1:1 (сравнено с палитрой): `R1_base` = `#385781`,
  `R3_panel` = `#39859C` после пересборки (2026-10-18).

Перенесено из проверок проекта-предшественника и **в FrostSpace не перепроверялось**:

- `ReadPixels` отдаёт линейные значения, PNG — sRGB;
- `material.mainTexture` в URP не читается, нужен `SetTexture("_BaseMap")`;
- камера, созданная кодом, не получает `UniversalAdditionalCameraData` автоматически;
- поведение Quaternius-материалов с `Alpha = 0` в превью Blender.

Эти пункты — рабочие правила, но при первом реальном использовании их нужно подтвердить
на конкретном ассете и записать результат.

## Чек-лист перед «готово»

1. Модель в метрах, оси проверены.
2. Габарит после импорта совпадает с задуманным (числом, не на глаз).
3. Материал использует `_BaseMap`; цвет не пересвечен.
4. Flat shading сохранён, лишние материалы не созданы.
5. `.meta` на месте; пак лежит в `ThirdParty` с `SOURCE.md`.
6. В `Assets/` нет `.blend`, скриншотов и временных файлов.
